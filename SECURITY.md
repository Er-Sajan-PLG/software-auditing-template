# Security Policy

## Supported versions

USAT is distributed as a CLI and a set of YAML rule packs. We patch the
latest release.

| Version | Supported |
| ------- | --------- |
| 1.x     | ✅        |
| < 1.0   | ❌        |

## Reporting a vulnerability

**Please do not open a public issue for security vulnerabilities.**

Use GitHub's private reporting instead:

<https://github.com/Er-Sajan-PLG/software-auditing-template/security/advisories/new>

Include:

- what the issue is and why it matters
- a reproducer (a repository or a minimal file set is ideal)
- the affected rule, file, or CLI flag
- the impact you believe it has

You should get an acknowledgement within **7 days** and a status update within **30**.

## Scope

**In scope**

- The `usat` CLI: anything that causes it to crash, hang, or behave unexpectedly on
  untrusted input
- Rule packs: a rule that produces a false sense of security (a check that passes when
  the condition is genuinely absent), or a pattern that is trivially evaded
- Detection: facts that are reliably wrong in a way that hides findings
- Anything that causes USAT to read or exfiltrate data it should not

**Out of scope**

- Findings USAT reports about _your_ project. Those are features working as intended —
  even the inconvenient ones.
- Vulnerabilities in third-party projects that USAT merely audits.
- Reports generated by an older version, unless they reproduce on the latest.
- Theoretical issues with no demonstrable impact.

## A note on what USAT is

USAT checks **hygiene and process**: is a lockfile committed, are secrets absent, is
CI configured, is provenance attested. It is deliberately not a penetration test, and a
clean USAT report is **not** evidence that an application is secure.

If you are reporting a vulnerability in a project that uses USAT, report it to that
project — not here.
